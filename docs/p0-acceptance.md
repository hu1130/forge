# P0 可行性验收

P0 的目的不是实现 UI，而是验证选定底座不会阻断最终范围。

## 必须通过

1. 固定一个 Codex CLI / App Server 版本，并保存与该版本一致的 TypeScript 和 JSON Schema。
2. App Server 可通过 `stdio` 完成 `initialize` / `initialized` 握手，探针不得读取或输出密钥。
3. 以下路径分别完成真实测试：OpenAI、Claude、Gemini、DeepSeek、通义千问、智谱、Moonshot、Ollama。
4. 每个路径至少验证流式文本、一次工具调用和取消；支持图片的目标模型还必须验证图片输入。
5. 任一路径无法保持工具调用或取消语义时，停止进入 P1，记录失败证据并请求架构决策；不得自动降级或切换厂商。

## 当前状态定义

- `passed`：本机自动化或真实厂商调用已通过，并有可复现证据。
- `blocked`：缺少 API Key、本机服务或用户授权；不等同于失败。
- `failed`：已具备测试条件但行为不符合契约。
- `pending`：尚未执行。

## 实测输入安全规则

- 探针只检测环境变量是否存在，绝不打印值。
- API Key 不写入仓库、命令参数、测试快照或日志。
- 厂商实测使用最小无敏感内容的固定提示词和只读测试工具。
- 不使用 ChatGPT 登录态替代用户要求的 API Key 测试。
