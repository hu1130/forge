# 知识库问答与检索增强生成（RAG）

知识库问答系统通常先把自己的私有资料整理成可检索的文档，再在回答问题时先定位相关片段，最后生成带依据的答案。这样可以避免模型凭空编造，也让回答可以追溯到原始资料。

检索增强生成（Retrieval-Augmented Generation，简称 RAG）是目前最常见的知识库问答实现思路。RAG 的完整流程一般包括：文档解析、文本清洗、分块、把分块建成索引、用户提问时检索相关片段、可选的重排，以及最后让大模型基于片段生成答案。

文档分块是影响检索质量的关键环节。块太大会混入无关内容，块太小又缺少上下文。常见的做法是按段落或句子切分，并保留少量重叠，避免关键信息恰好被切到两个块里。

用于检索的索引可以分为两类。一类是关键词倒排索引，例如 BM25，速度快、可解释、不需要模型；另一类是向量索引，需要先对文本做向量化（Embedding），擅长处理语义相近但用词不同的情况。

RAG 与传统的微调模型相比，优点包括：资料更新只需要替换文档而不需要重新训练；回答会附带引用片段，便于人工核对；对私有资料和权限控制也更友好。

# 本演示项目 kb-qa 的实现说明

kb-qa 是一个“离线可跑、可平滑升级”的知识库问答演示。它默认使用本机文档加轻量检索（中文分词 + BM25），不依赖任何大模型 API Key，启动后即可完整演示问答和引用展示。

演示的检索流程是：启动时读取 data 目录下的 Markdown 文档，按段落切分成块；提问时对问题做同样的中文分词，用 BM25 计算每个块与问题的相关性，返回得分最高的前三个片段作为引用。

如果需要升级为“检索 + 大模型生成”，只需要配置一个 OpenAI 兼容的 API Key。服务会通过环境变量自动检测，配置后同一套接口自动切换为带上下文的生成模式，无需改动代码。

本演示支持三个环境变量：KB_LLM_API_KEY 表示模型 API Key，KB_LLM_MODEL 表示模型名称（默认 deepseek-chat），KB_LLM_BASE_URL 表示 OpenAI 兼容的接口地址（默认 DeepSeek 官方地址）。未配置 Key 时，接口保持离线模式运行，不会发起任何外部网络请求。

更换知识库内容时，把新的 Markdown 文件放入 data 目录，再调用一次 POST /api/reload，或直接重启服务即可生效。

# FastAPI 简介

FastAPI 是一个基于 Python 类型标注的现代 Web 框架，常用于构建后端 API。它自带数据校验、依赖注入和异步支持，并且会根据代码自动生成 OpenAPI 文档。

使用 FastAPI 时，开发者只需要定义 Python 函数和类型注解，FastAPI 会自动完成请求参数校验与序列化。访问 /docs 页面可以看到交互式的接口文档，方便直接调试。

FastAPI 通常搭配 Uvicorn 运行。Uvicorn 是一个轻量的 ASGI 服务器，一条命令即可启动服务：python -m uvicorn app.main:app --reload。

# 新能源汽车基础概念

新能源汽车指使用非传统燃油作为动力来源的汽车，主要分为纯电动汽车、插电式混合动力汽车和燃料电池汽车等类型。

纯电动汽车完全依靠动力电池供电，依靠电机驱动，结构相对简单，日常使用成本较低。影响纯电动汽车体验的核心指标包括电池容量、续航里程和充电速度。

插电式混合动力汽车同时具备发动机和电机，短途可以纯电行驶，长途或电池电量不足时可以靠燃油继续行驶，缓解了续航焦虑。

动力电池是新能源汽车的核心部件，常见的类型包括磷酸铁锂电池和三元锂电池。磷酸铁锂电池安全性较好、循环寿命长，三元锂电池能量密度更高。电池管理系统负责监控电池温度、电压和电流，保证充放电安全。
